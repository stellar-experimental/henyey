### Diagnosis (high-confidence, instrumented)
Ceiling = **size of the SCP-agreed (externalized/applied) tx set per round**. Ruled out: apply speed (close 30–40 ms ≪ ~5 s cadence), inclusion/surge logic (nominator includes *all* it has, no trim), tx-set capacity (~50–55% full), per-node flood starvation (`available` scales 1075→1350), sync breaks (all 23 `Synced!`). **Mechanism**: each node nominates ~1350 but only ~1100 are externalized/applied (median 1023–1231 @252) → uneven inter-node tx-flood propagation; nodes hold overlapping-but-different pending sets, so the agreed set < nominated, and runs >~225 leave a straggler tail.

### iter 8 outcome — queued flood-divergence lever FALSIFIED (source audit)
The queued iter-8 lever ("henyey defers advert, core broadcasts on reception") is a **phantom**. Reading the authoritative core source: `TransactionQueue::broadcast(false)` on tx-receipt does **not** broadcast — it only arms `mBroadcastTimer` for one flood period and explicitly waits ("don't do anything right away, wait for the timer"); the flood happens in the periodic `broadcast(true)` callback. That is exactly henyey's periodic `flush_tx_adverts`. The pull side (`TxDemandsManager` ↔ henyey `run_tx_demands`) is likewise a faithful port (same period/backoff/`MAX_RETRY_COUNT=15`/round-robin demand build). **Conclusion: the flood/propagation subsystem has no throughput-relevant henyey↔core divergence.** The misleading "unlike stellar-core's immediate broadcast" comment in `tx_flooding.rs` should be corrected.

### Where the remaining gap lives (redirected)
The agreed<nominated gap (each node nominates ~1350 but only ~1100 externalize/apply) is **not** a flood-timing artifact. It must live in either (a) **SCP convergence** — nomination/ballot timing under load producing a smaller agreed composite set than the union of nominations, or (b) **tx-set fetch/assembly** — a node externalizes a tx-set hash it doesn't fully hold and can't assemble the full set before the apply deadline. Both are deep, parity-sensitive (SCP wire + tx-set hashes are observable surface); the parity-safe room is internal *speed* (fetch parallelism, assembly cost), not protocol timing. The honest next step is **profiling under load** to localize the loss, not another blind divergence hunt — the divergence hunt on the flood path is now exhausted.
